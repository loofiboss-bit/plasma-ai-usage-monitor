## GitHub

### AI Usage Monitor 25.0.0 — Searchable Session History

A KDE Plasma 6 panel widget for API usage, costs, coding-tool quotas and
optional local session history.

Find local Codex and Claude Code sessions by project and reported model. Search
complete project/model choices, keep the active selection visible, and move
between summaries, daily totals, analysis and session details without losing
your filters. Manual JSON/CSV exports use the same selection and stream to
private atomic files.

This release also fixes deleted Codex totals returning after rescans, resumes
past oversized log records, rejects outdated Overview results, and adds clear
search/filter reset actions. Source verification distinguishes reporting,
connectivity, waiting, warnings and failures.

Local collection remains independently opt-in for each tool. Prompts, replies,
local paths and aliases are excluded from session exports. Existing settings,
aliases and retained history remain compatible.

Start on Fedora:

```sh
sudo dnf copr enable loofitheboss/plasma-ai-usage-monitor
sudo dnf install plasma-ai-usage-monitor
```

For an existing installation, run `sudo dnf upgrade --refresh plasma-ai-usage-monitor`.
Log out and back in, open **Add Widgets**, and search for **AI Usage Monitor**.
Enable optional Codex or Claude Code session data in **Settings → History**
and choose **Apply**, then explore **History → Sessions**.

The [COPR package](https://copr.fedorainfracloud.org/coprs/loofitheboss/plasma-ai-usage-monitor/)
includes both the Plasma frontend and native plugin.
The [KDE Store](https://store.kde.org/p/2353976) and `.plasmoid` asset contain the
frontend only and require the matching 25.0.0 native plugin. Read the
[installation and first-setup guide](https://github.com/loofiboss-bit/plasma-ai-usage-monitor/wiki/Installation). Checksums and build provenance must be read back from the
published release before claiming delivery.

physical Plasma scaling, screen-reader operation, live provider accounts or
public availability. Report those results separately using the qualification
checklist. Publication requires the verified stable tag on the exact `main`
commit, the canonical Release workflow, GitHub assets/checksums/provenance,
