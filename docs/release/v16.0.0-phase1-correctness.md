# v16.0.0 Phase 1 Correctness and Gate Report

- Date: 2026-07-26
- Branch: `main`
- Stable version: `15.0.0`
- Target version: `16.0.0`

Phase 1 closes the two correctness defects recorded in the Phase 0 baseline and
turns QML lint, release-media identity, and cross-surface version alignment into
enforced repository gates. It does not change the stable version, publish a
release, or add Phase 2 runtime features.

## Analyst range contract

Analyst requests, SQL, coverage, and reports now use one UTC half-open interval:
`[fromInclusive, toExclusive)`.

- 7, 30, and 90 day selections contain exactly that many 24-hour UTC days.
- SQL excludes observations exactly at `toExclusive`.
- The report presents the final included date while retaining the exclusive
  boundary in the data contract.
- QML table tests cover UTC, Stockholm spring and autumn DST boundaries, and a
  New York spring DST boundary.
- The database regression test proves that the upper-bound observation is
  excluded.

## Zero-warning QML lint

The native module now emits declarative QML type information from its C++ type
registrations. Shipped QML uses the localized context injected by Plasma and
declares runtime context such as the monitor object at component boundaries.

`scripts/qml_lint.py` supplies the built module import path, rejects every
warning, and writes `build/debug/qml-lint-report.json`. It narrowly filters
qmllint's `unqualified` false positive when the referenced symbol is one of
Plasma's injected translation functions; all other warnings remain
release-blocking. The verified report contains 65 files and zero warnings.
Narrow suppressions remain only where upstream Plasma type information cannot
describe an injected runtime property.

## Release-media evidence

The capture workflow now uses isolated HOME and XDG directories for each view
and for the nested Plasma panel. The nested desktop removes existing panels and
widgets and uses a controlled solid-color wallpaper.

Every capture records and validates:

- the expected process ID;
- the exact KWin window identity and caption;
- a view-specific AT-SPI marker before and after capture.

The media manifest carries this evidence for new v16 media. A mutation test
proves that a wrong active window or changed accessibility marker is rejected.
The nine historical v15 assets remain valid under their recorded source
manifest; new v16 captures must satisfy the stronger evidence contract.

## Version policy

`scripts/check_version_policy.py` keeps stable `15.0.0` and planned `16.0.0`
consistent across:

- `VERSION` and the roadmap;
- `SECURITY.md`;
- package and required-plugin metadata;
- provider and subscription catalogs;
- the RPM spec;
- the latest AppStream release;
- the canonical v16 plan target.

Mutation coverage deliberately changes roadmap, security, package metadata,
AppStream, RPM, and catalog versions and requires every mismatch to fail.

## Compatibility boundary

Phase 1 does not change:

- package ID, native QML URI, notifyrc, or install surfaces;
- KConfig, KWallet folders or identifiers, or export schema;
- SQLite schema v4, history location, or retention;
- provider/subscription behavior or metric truth semantics;
- the stable `VERSION` or any public release surface.

The QML plugin registration mechanism changes from manual registration to
Qt-generated declarative registration while preserving the public native URI
and exposed type names.

## Verification

The implementation is accepted by the repository's focused range, QML,
release-media, and version-policy tests plus the broad build, test, lint,
performance, release, strict-import, and offscreen-smoke gates documented in
the canonical v16 plan.
