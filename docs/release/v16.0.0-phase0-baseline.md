- Date: 2026-07-26

- Commit: `d51f597ebb0d23f7572c8d9d65f4ecf0beb85396`

The implementation baseline was clean and matched `origin/main`. Phase 0 keeps
all release metadata at the stable version; `VERSION` changes only during a
later authorized release-preparation phase.

## Repository review

- The runtime exposes 18 provider profiles and 7 subscription-tool profiles.
- `DailyStateModel` and `SourceReadinessModel` are the shared typed source truth.
- Provider metrics preserve availability, source, quality, semantic, scope,
  window, currency, and reset boundaries.
- KWallet folder `ai-usage-monitor` has no plaintext fallback.
- SQLite remains at schema/user version 4 with asynchronous History and Analyst
  requests.
- Scheduled provider monitoring is read-only and the release gate rejects
  inference or mutating endpoints.
- COPR/source packages remain the complete distribution because the widget
  requires the matching native QML plugin.

## Confirmed audit findings

1. **Deferred to Phase 1:** Analyst constructs local calendar bounds that become a 31-day UTC range for
   a nominal 30-day Stockholm period.
2. **Deferred to Phase 2:** Overview repeats quota/reset facts across multiple cards and lacks a
   source-first drill-down.
3. **Deferred to Phase 3:** History can clip its rightmost axis label and its “Detail” mode is ambiguous.
4. **Deferred to Phase 3:** Analyst KPI cards do not use wide space effectively.
5. **Deferred to Phase 1:** The current release-media gate can accept the wrong foreground window.
6. **Deferred to Phase 4:** Anthropic still operates as connectivity/rate-limit-only despite the
   provider's read-only organization Usage and Cost APIs.
7. **Resolved in Phase 0:** `SECURITY.md` and the v15 plan status were stale.
8. **Resolved in Phase 0:** `dashboardMode` and `showOnlyProblems` were defined and exported but unused.

## Phase 0 compatibility boundary

Phase 0 does not change:

- `VERSION`, package metadata, catalogs, RPM spec, or AppStream release;
- Plasma package ID or native QML URI;
- KWallet folder, stored values, or secret identifiers;
- SQLite schema v4, database path, retention, or stored history;
- provider metric, daily-state, notification, History, or Analyst behavior;
- release publishing, active desktop settings, or installed packages.

Phase 0 retires only `dashboardMode` and `showOnlyProblems`. New schema-v2
configuration exports omit them. Existing schema-v2 payloads may contain them
and import all other supported settings while these two values are ignored.
Existing on-disk Plasma configuration is not actively rewritten or deleted.
