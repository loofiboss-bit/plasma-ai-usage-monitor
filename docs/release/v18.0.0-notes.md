# AI Usage Monitor 18.0.0 — Budget Control

Budget Control replaces fixed per-provider daily and monthly limits with local,
typed policies that understand real calendar and billing periods, provider
scope, cost evidence and safe-to-spend guidance.

## Highlights

- Create, duplicate, enable, snooze and remove independent policies through a
  searchable staged editor. Nothing is saved until Apply.
- Use calendar day, Monday ISO week, calendar month or anchored month periods
  in the policy's saved IANA time zone. Stable authenticated provider resets
  are accepted only when the reviewed catalog contract supports them.
- See spent, remaining, consumed percentage, projected period end, predicted
  overrun, safe today, remaining daily allowance, sample/coverage evidence and
  compatible previous-period comparison.
- Keep actual and estimated costs, currencies and scopes separate. Missing data
  never becomes zero and the widget never performs currency conversion.
- Budget aggregate, OpenAI project/line-item, Anthropic reported dimensions and
  validated LiteLLM gateway scopes without inventing attribution. Source Detail
  reports `Unattributed` when compatible scoped totals do not reach aggregate.
- Persist warning, critical, exceeded, recovery and period-reset transitions
  before delivery. DND, cooldown, snooze, delivery failure and restart cannot
  lose or duplicate the transition.
- Keep exactly three popup tabs—Overview, History and Insights—and lazy-load
  secondary queries and scope rows.
- Add transactional SQLite schema v6, config backup schema v3, catalog v6 and
  focused policy/cycle/pacing/query components.

## Compatibility and rollback

The package, QML, AppStream, notification and KWallet identities remain stable.
Schema v6 migration creates a `.v18-backup`, preserves observations and legacy
guardrail tables, and leaves the hidden v17 daily/monthly KConfig keys intact.
Each applet instance migrates once, so deleted migrated policies stay deleted.

Config schema v3 restores settings and policies atomically. Schema v2 remains a
settings-only import. An explicit local v3 backup may contain provider scope
identities needed for exact restoration; treat that file as sensitive. Secrets
remain in KWallet and are never included.

Rolling back the RPM does not delete configuration, KWallet entries or the
schema-v6 database. v17 continues to read its unchanged legacy budget keys and
ignores v18-only tables. Keep the `.v18-backup` for application-level database
rollback.

## Safety and privacy

All policy calculations are local and deterministic. v18 adds no inference,
provider mutation, cloud service, automatic model switching, FX or invoice
import. Raw project/workspace/model/line-item identities remain local and are
excluded from diagnostics, support reports, webhooks and Prometheus labels.
External transition payloads contain only provider display name, risk class,
coarse percentage class, period and local link text.

See the [Budget Control guide](../user-guide/runway-guardrails.md) for exact
period, pacing, unavailable, scope and notification semantics.
