## First-success behavior

- [ ] A Store-only install renders native-plugin recovery without importing the native module first.
- [ ] Missing, older, newer, matched, and runtime-load-failure plugin states show the right versions and next action.
- [ ] Repairing the plugin and restarting Plasma preserves configuration, KWallet entries, and history.
- [ ] Guided first success configures one provider or detected local tool without opening unrelated settings.
- [ ] Guided verification uses the scheduled read-only contract and never sends inference.
- [ ] The result identifies provider usage or spend, gateway data, balance, local estimate, or connectivity only.
- [ ] Skipping setup records no successful source and allows setup to resume.

## Settings, Overview, and Diagnostics

- [ ] Provider Settings shows a source list and one selected detail pane at a time.
- [ ] Search and monitoring-level filters remain usable with keyboard focus and screen-reader names.
- [ ] Cancel discards staged KWallet writes and removals; Apply commits them once.
- [ ] Verification stays disabled until pending settings are applied.
- [ ] Overview separates reporting providers, balances, local estimates, connection checks, and sources needing attention.
- [ ] Unknown stays distinct from zero in the UI, history, exports, alerts, and Prometheus output.
- [ ] Native Diagnostics reports frontend/plugin identity, install layers, database health, source readiness, KWallet, and catalogs.
- [ ] Repair, version-check, capability-report, and support-report copy actions work from an installed package.
- [ ] Support-report redaction tests cover endpoint hosts, query strings, account IDs, project IDs, credentials, and KWallet values.
