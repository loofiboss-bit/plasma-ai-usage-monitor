# V25.0.1 — RPM Build Dependency Correction

This patch declares the KDE KCMUtils build dependency used by the History
settings QML tests. Its absence caused the V25.0.0 COPR Fedora 43 build to fail
at `%check` in a clean buildroot. A dedicated Fedora 43 RPM CI job now covers
that package path alongside Fedora 45. Both jobs run without the global
development-mode override. The published V25.0.0 tag remains unchanged.

V25.0.1 retains searchable local Codex and Claude Code history, project and
model filters, custom date ranges, consistent summaries and private manual
JSON/CSV exports. It does not change session behavior or data formats.

## Install or upgrade

On Fedora, the [COPR package](https://copr.fedorainfracloud.org/coprs/loofitheboss/plasma-ai-usage-monitor/)
includes both the widget and matching native plugin. Check its available builds
for your Fedora release; Fedora 44 remains the release baseline.

```sh
sudo dnf copr enable loofitheboss/plasma-ai-usage-monitor
sudo dnf install plasma-ai-usage-monitor
```

Existing users can run `sudo dnf upgrade --refresh plasma-ai-usage-monitor`.
Log out and back in, then check that both versions are **25.0.1** in
**Settings → Diagnostics**. Add **AI Usage Monitor** through Plasma's
**Add Widgets** menu if it is not on your panel yet.

The [KDE Store download](https://store.kde.org/p/2353976) and GitHub `.plasmoid`
asset contain only the frontend. They require the matching **25.0.1 native
plugin**. Fedora COPR users already have both parts. For other Plasma 6
systems, follow the [source installation guide](https://github.com/loofiboss-bit/plasma-ai-usage-monitor/blob/main/docs/user-guide/installation.md#guided-source-install).

## Existing users

SQLite schema v9, configuration schema v3 and session-export schema v1 are
unchanged. Settings, aliases, history and independently enabled session imports
are retained; no migration, data deletion or reimport is required for this patch.

New users can follow the [first-setup guide](https://github.com/loofiboss-bit/plasma-ai-usage-monitor/wiki/Getting-Started).
For local sessions without an API key, enable **Codex session data** or
**Claude Code session data** in **Settings → History**, choose **Apply**, wait
for the scan and open **History → Sessions**.
